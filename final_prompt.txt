Role & Objective
- Role: Senior Python engineer and build/release captain.
- Objective: In a single pass, implement and deliver a persistent, modular, concurrency-safe Advanced Tag System for a TODO application while preserving the existing public API from the legacy in-memory implementation. Produce code, tests, docs, and one-click scripts; execute the full test suite and auto-fix issues until all tests pass.

Inputs & Context
- Legacy app: An existing minimal in-memory TODO list where tags are plain strings and there is no persistence, metadata, advanced filtering, concurrency protection, or extensibility. You must preserve the current public API exposed by the legacy module (backward compatibility requirement).
- Environment: Standard Python 3.x environment with ability to run pytest and install dependencies. Use local files and relative paths. No external services required.

Step-by-Step Instructions
1) Backward Compatibility
- Enumerate and preserve every public function and behavior from the legacy TODO module. Provide a wrapper module that exposes the same API and semantics so existing callers are unaffected.

2) Modular Architecture
- Create a package with clear boundaries and testable components:
  - storage.py: persistent storage layer (SQLite preferred; JSON with proper file locking is acceptable). Provide init/migrations, thread-safety, transactions/WAL, and simple schema evolution hooks.
  - models.py: structured data models (tasks, tags, relationships; created/updated timestamps).
  - tags.py: tag business logic, aliases, colors, descriptions, usage counters, co-occurrence tracking, and recommendation utilities.
  - query.py: a mini-DSL query engine (tokenizer, parser with parentheses and AND/OR/NOT, tag:NAME operator, bare-word token handling, scoring and extensibility points for future operators).
  - plugins.py: plugin discovery and lifecycle with hooks (on_task_added, on_tag_added, on_task_completed) and safe isolation.
  - cache.py, utils.py: small helpers for caching, timing, paging, fuzzy matching, color output, and concurrency primitives.
  - cli.py: enhanced CLI with fuzzy search, colorized output, paging, and the ability to run DSL queries.
  - api.py: cohesive programmatic API for high-level operations (query, recommend, stats, etc.).
  - __init__.py: export package-level entry points.

3) Persistent Storage & Concurrency
- Use SQLite with WAL mode and transactions by default (or JSON with robust advisory/file locking if chosen). Ensure:
  - Safe concurrent reads/writes without corruption.
  - Predictable isolation; updates are atomic.
  - Storage survives restarts and supports simple schema evolution.
  - Thread-local or connection-per-thread strategy with a safe write lock for mutating operations.

4) Structured Tag Model
- Implement tags with:
  - Aliases (bi-directional mapping, e.g., “work” ↔ “office”).
  - Colors for CLI display.
  - Descriptions.
  - Created/updated timestamps.
  - Usage counters that update on tag assignment/removal.
  - Tag co-occurrence graph updated on task mutations.

5) Tag Recommendations
- Provide recommendation API using a blend of:
  - Keyword similarity against tag names/descriptions.
  - Historical co-occurrence.
  - Usage frequency weighting.
- Keep implementation lightweight and deterministic; allow future extension.

6) Query Language (Mini DSL)
- Support expressions like: tag:work AND (urgent OR personal) AND NOT archived.
- Requirements:
  - Tokenizer handles identifiers, tag:name, quoted strings, parentheses, AND/OR/NOT, and bare words.
  - Parser supports precedence via parentheses and boolean operators.
  - Evaluator matches both task text and tag names for bare words; implement a simple scoring.
  - Provide clear extension points to add new operators later.

7) CLI Enhancements
- Add commands to:
  - Add/list/complete tasks with tags.
  - Run DSL queries.
  - Fuzzy search tasks/tags.
  - Output colorized results and page through long lists.

8) Backward-Compatible Wrapper
- Implement todo_advanced.py as a drop-in API wrapper that preserves all public functions and behaviors from the legacy module but delegates to the new implementation.

9) Tests & Tooling
- Create tests under tests/ covering:
  - Persistence behavior across restarts.
  - Concurrency behavior and lack of corruption under concurrent writes.
  - DSL tokenization, parsing, operator semantics, and scoring.
  - Tag metadata, usage counters, aliases, and recommendations.
  - CLI commands (smoke level) and plugin hooks.
  - Property-based tests (Hypothesis) for random queries and simultaneous operations.
  - Lightweight performance smoke tests (e.g., 10k tasks) printing timing metrics.
- Provide:
  - perf_test.py for basic performance validation.
  - pytest.ini for configuration.
  - requirements.txt and requirements-dev.txt capturing runtime and test/dev deps.
  - FEATURE_SPEC.md describing the feature set.
  - README.md with overview, usage examples, and one‑click testing instructions.
  - One‑click scripts: run_tests.sh and run_tests.ps1 to create/activate a venv, install deps, run pytest, and print performance metrics.

10) Performance Targets
- Load 10,000 tasks in < 80 ms on a typical developer machine.
- Typical DSL queries in < 50 ms (warm cache).
- Tag-relationship updates in < 10 ms.
- No corruption or lost updates under concurrent writes.

11) Execute and Auto-Fix Until Green
- Create/activate a local virtual environment, install dependencies, and run the full pytest suite.
- If any tests fail, read the pytest failure messages, fix the relevant implementation deterministically, and rerun pytest.
- Repeat this edit–test loop autonomously until all tests pass in the same execution.
- Emit a concise test summary and performance timings on completion.
