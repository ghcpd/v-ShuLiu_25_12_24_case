Role & Objective
You are a senior software engineer and prompt engineer. Implement an advanced, persistent, modular, and concurrency-safe Tag System for an existing minimal TODO application while preserving the original public API and making the entire solution testable, extendable, and performant. Additionally, ensure that after implementation, all automated tests pass without requiring further interaction.

Inputs & Context
- Codebase context: There is an existing minimal in-memory TODO application with plain string tags in todo_original.py. It lacks persistence, structured tag metadata, advanced filtering/DSL, concurrency safety, and a plugin system.
- Your task is to deliver a complete upgraded Tag System and surrounding modules, tests, and scripts within the current working directory.
- Persistence choice: Use SQLite for durability, concurrency, and performance. (A storage abstraction must allow future JSON-with-locking as an alternative backend.)

Step-by-Step Instructions
1) Project Structure and Backward Compatibility
   - Preserve todo_original.py unchanged and maintain backward compatibility at the API level in a new wrapper module todo_advanced.py. All existing public API functions must behave exactly as before for callers using todo_original.py.
   - Add a modular package-style layout using top-level Python modules for: models.py, storage.py, tags.py, query.py, plugins.py, cli.py, todo_advanced.py.

2) Data Models (models.py)
   - Define models for Task and Tag with strong typing. Include for Tag: aliases (bidirectional support), color (string or enum), description, created_at, updated_at, usage_count, and co_occurrence relationships to other tags with counts.
   - Define Task fields to support: id, title, description (optional), created_at, updated_at, completed_at (nullable), tags (list of tag IDs or names), and status flags (e.g., completed).
   - Provide (de)serialization schemas for persistence with SQLite rows.

3) Storage Layer (storage.py)
   - Implement a SQLite-backed Storage class providing safe CRUD for tasks, tags, and tag relationships. Include simple schema evolution (version table + migration steps).
   - Guarantee concurrency safety with RLock or equivalent and use transactions for all write operations. Ensure snapshot-style reads to avoid inconsistent states.
   - Expose clearly scoped methods: create/update/delete Task, create/update/delete Tag, manage aliases, update usage counters, update co-occurrence counts, and query by DSL results.
   - Ensure durability and survive restarts. Include initialization that creates tables if absent and handles migrations idempotently.

4) Tag Logic (tags.py)
   - Implement tag operations: create/update/delete tags; manage aliases (aliases are symmetric); set/get color and description; update and read usage counters and co-occurrences.
   - Implement tag recommendations using: (a) keyword similarity between tag name/description and input text, (b) co-occurrence history, and (c) usage frequency. Return ranked suggestions with scores.
   - Provide utilities to normalize tag names (case and whitespace handling) while preserving display casing.

5) Query Language DSL (query.py)
   - Implement a mini-DSL with tokenization, parsing, and evaluation for queries like: tag:work AND (urgent OR personal) AND NOT archived.
   - Support operators: AND, OR, NOT; parentheses; prefix operators like tag:<name>, text:<keyword> (exact/contains), completed:true/false, and date filters (created>=, updated<=) extensible via a registry.
   - Return matched tasks ordered by relevance score (e.g., keyword matches + usage signals), with a pluggable scoring function.

6) Plugin System (plugins.py)
   - Implement auto-discovery of plugin modules from a plugins/ namespace or entry-point-like scanning. No external packaging required; modules found in a plugins directory should be imported safely.
   - Provide hooks: on_task_added, on_task_completed, on_tag_added, on_tag_updated, on_task_tagged, and pre/post-query hooks. Allow plugins to register custom DSL operators.
   - Ensure plugins cannot crash the core: wrap calls, log errors, and continue.

7) CLI Enhancements (cli.py)
   - Provide commands for adding/listing/completing/removing tasks; managing tags (create/update/aliases/colors/descriptions); running DSL queries; and viewing recommendations.
   - Add fuzzy search for tasks/tags; colorized output; and paging for long results. Ensure Windows-friendly behavior.
   - Make the CLI operate through todo_advanced.py, not directly on storage.

8) Advanced Wrapper API (todo_advanced.py)
   - Preserve the original public API semantics from todo_original.py. Implement the advanced behavior underneath using the new storage, tags, query, and plugins modules.
   - Provide thread-safe functions: add_todo, list_todos, complete_todo, delete_todo, add_tag_to_todo, list_tags, search/query, and metadata accessors.
   - Ensure swapping between backends (SQLite now, JSON-with-locking later) via an internal interface; default to SQLite.

9) Tests (tests/)
   - Add automated tests covering: persistence correctness (restart-safe), concurrency behavior (no corruption under simultaneous writes), DSL parsing/evaluation, tag metadata (aliases/colors/descriptions/timestamps/usage/co-occurrence), CLI commands, and plugin hooks.
   - Add property-based tests (Hypothesis) for randomized queries and concurrent operations. Ensure tests are deterministic and isolated (use temporary DB files per test).
   - Provide performance and stress tests that load 10k+ tasks and run representative queries.

10) Performance Validation (perf_test.py)
   - Implement a benchmark script that:
     - Inserts 10,000 tasks with varied tags.
     - Measures: load time (< 80 ms target), typical DSL query latency (< 50 ms), and co-occurrence update latency (< 10 ms).
     - Prints summary metrics and fails with a non-zero exit code if targets are not met (configurable thresholds).

11) One-Click Test Scripts and Docs
   - Provide run_tests.sh and run_tests.ps1 that:
     - Create/activate a virtual environment.
     - Install dependencies from requirements.txt and dev-only from requirements-dev.txt.
     - Run the full pytest suite with verbose output and then run perf_test.py.
   - Provide README.md with overview, setup, usage examples (API + CLI + DSL), plugin guide, and test instructions.
   - Provide FEATURE_SPEC.md summarizing the advanced tag system’s capabilities and architecture.

12) Dependencies
   - Provide requirements.txt for runtime (e.g., colorized CLI and fuzzy search libraries) and requirements-dev.txt for testing (pytest, hypothesis, coverage tools). Pin versions or minimum-compatible specifiers.

13) Make Tests Pass (Single-Turn)
   - After implementing the above, execute the test suite and fix issues discovered by the tests so that all tests pass without further prompts or questions. Ensure isolated test environments (temporary DB per test) and avoid shared global state.
